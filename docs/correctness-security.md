# 정확성·보안 기준

이 도구의 결과는 근거로 쓰이므로, 수집 원천·금액 정밀도·탐색 순서·버전 고정을 아래 기준대로 지킵니다.

## 수집·저장

### 수집 원천

- 허용된 Token Contract·Transfer 이벤트·블록 구간만 수집한다.
- 수집 종료 블록은 수집 시작 시점의 `finalized` 블록 이하로 제한한다. 초과 요청은 CLI가 거부한다.
- RPC의 범위·결과 수 제한 오류가 나면 청크를 나눠 재시도한다.
- Approval과 `transaction.from/to`는 토큰 이동으로 쓰지 않는다.

### 데이터 모드

- Fixture와 RPC Snapshot을 분리한다.
- Fixture는 합성 데이터로 표시하고 실제 Explorer 링크를 넣지 않는다.

### 저장·게시

- 청크 저장과 체크포인트를 한 번에(원자적으로) 커밋한다.
- 전체 구간이 성공한 버전만 `READY`로 게시한다.

### 블록 해시 변경

- 재개할 때 마지막으로 커밋한 청크의 경계 블록 hash를 RPC와 대조한다.
- 다르면 관련 데이터셋·캐시를 무효화하고 새 버전으로 재수집한다.
- 이미 게시한 버전의 내용은 바꾸지 않는다.

### 금액 정밀도

| 위치 | 표현 |
| --- | --- |
| DB | `NUMERIC(78,0)` |
| Go | `big.Int` |
| JSON | 십진 문자열 |

float는 어디서도 쓰지 않습니다. 블록 번호도 JSON에서는 십진 문자열입니다.

## 경로·패턴

### 그래프 기준

- 노드는 주소, 원본 간선은 개별 Transfer 로그다.
- 자산은 `chainId + tokenAddress`로 구분한다.
- 간선 id는 Snapshot `{chainId}:{txHash}:{logIndex}`, Fixture `fx:{namespace}:{recordId}`다. 재수집해도 유지된다.

### 탐색 순서

- 같은 자산·범위에서 위치 `(blockNumber, transactionIndex, logIndex)`가 송신 방향은 엄격히 증가, 수신 방향은 엄격히 감소해야 한다.
- 같은 거래 안의 뒤 로그로 이어지는 전송은 허용한다.
- 주소만으로 방문 처리하지 않고, 서로 다른 근거 경로를 모두 보존한다.
- 후보 경로는 hop 수 → 경로 간선의 `(blockNumber, transactionIndex, logIndex, id)` 사전순으로 정렬한다.

### 탐색 상한

| 항목 | 값 |
| --- | --- |
| 깊이 | 기본 2, 최대 3 hop |
| 화면 노드·간선 | 200·500 |
| 후보 경로 | 10 |
| 탐색 상태 | 10,000 |
| 후보 전송 | 10,000 |
| 탐색 예산 | 2초 |

- 상한으로 중단하면 `truncated`, 사유, 발견 건수를 반환한다.
- 사유는 `PATH_LIMIT`·`STATE_LIMIT`·`CANDIDATE_LIMIT`·`NODE_LIMIT`·`EDGE_LIMIT`·`TIME_BUDGET` 중 하나다.
- 상태·시간 예산으로 중단하면 발견 건수는 하한값이다.

### 분산·합류 기준

- 600초 안에 고유 상대 주소가 3개 이상이면 FAN_OUT(송신) 또는 FAN_IN(수신)이다.
- 구간은 `[시작, 시작 + 600초)`이고, 시각은 `block.timestamp`(초) 기준이다.
- 0값·0주소 관련·자기 전송은 보존하되 기본 분석에서 제외한다.

### 패턴 근거

- 규칙 버전·Threshold·근거 전송·구간 불완전 여부를 기록한다.
- 구간(window)을 합치지 않는다. 근거가 같거나 다른 결과의 부분집합인 결과는 제거하고, 겹치는 결과는 묶어서 표시한다.
- 정상 배분·매출에서도 같은 형태가 나타날 수 있다.

### 해석 한계

- 경로만으로 특정 원금의 귀속이나 범죄 여부를 단정하지 않는다.
- 기존 잔액·범위 밖 이동·주소 소유자는 별도 정보가 필요하다.

## 화면·운영

### 버전·응답

- 요청·캐시·내보내기의 데이터셋 버전을 고정한다.
- 분석 전과 응답 전에 데이터셋 상태를 확인한다.
- 조건을 바꾼 뒤 도착한 이전 응답은 버린다.

### 화면·접근성

- 그래프·표·상세에 같은 전송 ID를 쓴다.
- 키보드와 표만으로 근거를 확인할 수 있게 한다.

### 비밀값·권한

- 분석 서버에는 개인키와 송금 기능을 두지 않는다.
- RPC·DB 비밀값, 개인정보, 비공개 실습 정답이 외부로 나가지 않게 막는다.

### 입력·외부 데이터

- 입력·요청 크기·호출량·탐색 비용을 제한한다.
- 외부 라벨·설명문을 실행 지시나 신뢰할 수 있는 HTML로 취급하지 않는다.
